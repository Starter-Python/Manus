# A1-1 과제 요구사항 점검표

이 문서는 과제 안내의 요구사항을 **저장소 안에서 자동으로 검증할 수 있는 항목**, **Git 이력으로 확인할 수 있는 항목**, **개인 개발 환경 또는 제출 화면에서 수동으로 확인해야 하는 항목**으로 나누어 정리합니다. “충족”은 이 저장소의 파일·실행 결과·Git 이력으로 확인한 상태를 뜻하며, “수동 확인 필요”는 VSCode 화면이나 개인 계정 설정처럼 저장소 코드만으로 대신할 수 없는 항목을 뜻합니다.

## 1. 최종 결과물 점검

| 요구사항 | 상태 | 근거 또는 확인 위치 |
| --- | --- | --- |
| 콘솔 기반 프롬프트 관리 프로그램 | 충족 | `prompt_manager.py`의 숫자 메뉴와 `main()` 반복문 |
| 프롬프트 추가·목록·카테고리·검색·상세·즐겨찾기 | 충족 | 메뉴 `1`~`7` 및 각 기능 함수 |
| 실행 중 데이터와 즐겨찾기 상태 유지, 종료 시 초기화 | 충족 | 한 실행에서 `prompts` 리스트를 공유하고 `create_initial_prompts()`에서 새 복사본 생성 |
| 기본 프롬프트 3개 이상 | 충족 | `DEFAULT_PROMPTS`에 6개 카테고리를 포함한 10개 등록 |
| GitHub 저장소에 코드 업로드 | 충족 | `Manus` 저장소의 `AI 활용 학습 A1-1` 경로가 `main`에 반영됨 |
| 의미 있는 커밋 10개 이상 | 충족 | `main`에 10개 이상의 커밋이 있으며 기능·문서·테스트·병합 단위로 구성됨 |
| 브랜치 생성 및 병합 기록 | 충족 | `feature/a1-1-prompt-list` 브랜치를 생성하고 `main`에 병합한 merge 커밋이 있음 |
| README에 설명·실행 방법·기능·카테고리 | 충족 | `README.md` |
| 기능별 함수 분리 | 충족 | `prompt_manager.py`의 함수별 docstring과 역할 분리 |

## 2. 프로그램 기능 요구사항 점검

| 번호 | 요구사항 | 상태 | 구현 방법 |
| --- | --- | --- | --- |
| 1 | 실행 시 메뉴 출력 | 충족 | `show_menu()`가 메뉴 `1`~`8`을 출력합니다. |
| 2 | 번호로 기능 선택 | 충족 | `get_menu_choice()`가 유효한 번호를 반환합니다. |
| 3 | 잘못된 메뉴 입력 안내 | 충족 | 유효하지 않은 값에는 안내 문구를 출력하고 재입력받습니다. |
| 4 | 종료 선택 시 프로그램 종료 | 충족 | 메뉴 `8`에서 인사 문구를 출력하고 반복문을 종료합니다. |
| 5 | 기능 수행 후 메뉴로 복귀 | 충족 | `main()`의 반복문이 기능 함수 실행 뒤 다음 메뉴를 출력합니다. |
| 6 | 기본 데이터 3개 이상 | 충족 | 텍스트 생성·이미지 생성·영상 생성·페르소나·자동화·기타를 포함한 예시 10개가 있습니다. |
| 7 | 리스트와 딕셔너리 사용 | 충족 | 전체 데이터는 `list[Prompt]`, 각 항목은 딕셔너리 구조입니다. |
| 8 | 제목·내용·카테고리·즐겨찾기 여부 포함 | 충족 | `Prompt` 타입과 모든 기본·추가 데이터에 네 필드가 있습니다. |
| 9 | 신규 프롬프트 등록 | 충족 | `add_prompt()`가 새 딕셔너리를 리스트에 추가합니다. |
| 10 | 빈 입력 재요청 | 충족 | `get_non_empty_input()`이 공백 입력을 막습니다. |
| 11 | 카테고리 선택 또는 직접 입력 | 충족 | `choose_category()`의 기본 번호와 `0. 직접 입력` 메뉴입니다. |
| 12 | 전체 목록의 번호·제목·카테고리·별 표시 | 충족 | `show_prompt_list()`가 항목별 요약과 `⭐`를 출력합니다. |
| 13 | 목록이 비었을 때 안내 | 충족 | `show_prompt_list()`가 빈 리스트를 처리합니다. |
| 14 | 카테고리별 조회 | 충족 | `show_prompts_by_category()`가 선택 카테고리로 필터링합니다. |
| 15 | 카테고리에 데이터가 없을 때 안내 | 충족 | 빈 필터 결과를 목록 출력 함수가 안내합니다. |
| 16 | 제목 또는 내용 기준 검색 | 충족 | `find_prompts()`가 두 필드를 모두 비교합니다. |
| 17 | 검색 결과 없음 안내 | 충족 | 빈 검색 결과를 목록 출력 함수가 안내합니다. |
| 18 | 번호로 상세 보기 | 충족 | `show_prompt_detail()`과 `get_prompt_index()`를 사용합니다. |
| 19 | 상세에 전체 내용과 모든 핵심 필드 표시 | 충족 | 제목·카테고리·즐겨찾기·내용을 순서대로 출력합니다. |
| 20 | 잘못된 프롬프트 번호 안내 | 충족 | 범위를 벗어나거나 숫자가 아니면 재입력받습니다. |
| 21 | 즐겨찾기 추가·해제 | 충족 | `toggle_favorite()`가 불리언 값을 반전합니다. |
| 22 | 즐겨찾기만 모아 보기 | 충족 | `show_favorites()`가 참인 항목만 필터링합니다. |
| 23 | 기능별 함수 분리 | 충족 | 입력, 등록, 조회, 검색, 즐겨찾기, 화면 출력이 독립 함수입니다. |

## 3. 자동 검증 결과

아래 명령은 A1-1 폴더에서 실행합니다.

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile prompt_manager.py
```

| 검증 대상 | 테스트 또는 검사 | 기대 결과 |
| --- | --- | --- |
| 기본 데이터 수와 필드 | `test_initial_prompts_have_ten_required_records` | 10개이며 6개 카테고리, 필수 키와 값 타입이 올바름 |
| 실행 간 데이터 독립성 | `test_initial_prompts_are_independent_between_runs` | 한 실행의 변경이 다음 실행의 기본 데이터에 영향을 주지 않음 |
| 프롬프트 번호 검증 | `test_prompt_number_validation` | 유효 범위만 참으로 판정 |
| 사용자 정의 카테고리 | `test_view_categories_include_custom_categories` | 직접 입력한 카테고리가 조회 목록에 포함됨 |
| 검색 | `test_find_prompts_searches_title_and_content` | 제목·내용 검색과 빈 결과가 올바름 |
| 중복 등록 방지 | `test_duplicate_prompt_ignores_case_and_extra_spaces`, `test_add_prompt_blocks_duplicate_without_changing_list` | 제목·내용이 같거나 공백 차이만 있는 항목을 다시 저장하지 않음 |
| 파이썬 문법 | `py_compile` | 문법 오류 없이 종료 |

## 4. 개발 환경 및 제출물 수동 확인 항목

다음 항목은 코드 파일만으로 완료 여부를 증명할 수 없으므로, 본인의 VSCode와 터미널에서 직접 확인하고 캡처해야 합니다. 이 항목들은 자동으로 완료라고 표시하지 않았습니다.

| 요구사항 | 상태 | 사용자 확인 방법 |
| --- | --- | --- |
| VSCode Python 확장 설치 | 수동 확인 필요 | VSCode 확장 화면에서 Python 확장을 확인합니다. |
| Korean Language Pack 설치 | 선택 사항 | 필요하면 VSCode 확장 화면에서 설치합니다. |
| VSCode GitHub 로그인 연동 | 수동 확인 필요 | VSCode 계정 메뉴에서 로그인 상태를 확인합니다. |
| Python 3.10 이상 | 수동 확인 필요 | `python3 --version` 실행 결과를 캡처합니다. |
| `print("Hello")` 실행 | 수동 확인 필요 | `hello.py`를 실행하고 출력 결과를 캡처합니다. |
| Git 버전 | 수동 확인 필요 | `git --version` 실행 결과를 캡처합니다. |
| Git 사용자 이름·이메일 | 수동 확인 필요 | `git config --global user.name`, `git config --global user.email`을 확인합니다. |
| 기본 브랜치 이름 `main` | 수동 확인 필요 | `git branch --show-current` 또는 `git config --global init.defaultBranch`를 확인합니다. |
| 공개 샘플 저장소 clone 확인 | 수동 확인 필요 | `git clone` 뒤 폴더 구조와 `git log --oneline`을 캡처합니다. |
| 개발 환경 설정 스크린샷 | 수동 확인 필요 | VSCode, Python 버전, Git 설정이 보이도록 촬영합니다. |
| 프로그램 실행 결과 스크린샷 | 수동 확인 필요 | 메뉴, 추가, 전체 목록, 검색 화면을 각각 캡처합니다. |
| `git log --oneline --graph` 스크린샷 | 수동 확인 필요 | 브랜치와 merge 커밋이 보이도록 캡처합니다. |

## 5. 최종 판정 기준

저장소의 프로그램 기능, 코드 구조, GitHub 반영, 10개 이상의 기능 단위 커밋, 브랜치 병합 기록은 모두 충족합니다. 반면 VSCode 확장·로그인·개인 환경·제출용 스크린샷은 실제 사용자의 화면이 필요한 항목이므로, 저장소에 코드가 올라가더라도 **수동 확인 필요** 상태로 남습니다.
