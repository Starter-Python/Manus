# 배포 화면 초기 조사 기록

## 확인 시각과 대상

2026-08-15에 관리된 배포 도메인 `a1ai-lab-coeomvfo.manus.space`의 첫 화면을 확인했다.

## 관찰 결과

페이지의 HTML 구조와 상단 메뉴·입력 컨트롤은 로드되었으나, 본문 문구와 이미지가 화면에 보이지 않았다. 본문에 쓰인 `reveal` 계열 요소가 숨김 상태에 머무르거나, 화면 진입을 처리하는 JavaScript가 실행되지 않은 상태가 유력하다. 동시에 이미지 경로가 `/manus-storage/...`로 제공되어, 정적 GitHub/Vercel 과제 폴더에서 쓰는 `assets/...` 경로와 일치하지 않는 배포본임을 확인했다.

브라우저 콘솔에는 즉시 표시된 오류가 없었다. 다음 점검에서는 실제 로드된 CSS·JavaScript 주소, 네트워크 응답, 버튼 이벤트 연결 여부를 확인하고, 배포 대상이 GitHub의 `AI 활용 학습 A1-3` 루트인지 검증한다.

## 원인 확인

배포 페이지의 모든 `.reveal` 요소는 계산된 CSS에서 `opacity: 0`인 상태였다. 화면 표시와 폼 이벤트 연결을 담당하는 `/app.js`를 가져와 확인한 결과, 응답 본문 길이가 `0`이었다. 따라서 화면 진입 시 `.is-visible` 클래스를 추가하는 JavaScript와 버튼 이벤트가 실행되지 않았고, 그 결과 본문이 공백처럼 보이며 버튼도 반응하지 않았다.

이 현상은 현재 관리된 배포가 Vite 기반 웹 프로젝트의 빌드 결과를 제공하는 반면, 과제용 바닐라 JavaScript 파일을 빌드 정적 자산으로 포함하지 않은 구조에서 발생했다. 수정은 빌드가 보장하는 `client/src` 진입점으로 상호작용 코드를 옮기거나, `client/public` 정적 자산으로 제공하는 방법으로 진행한다.

## 수정 후 개발 배포 확인

상호작용 스크립트를 Vite의 `client/src/app.js` 진입점으로 포함한 뒤, 첫 화면의 본문과 이미지가 정상 표시되었다. 빈 폼 제출 시 “현재 상태, 시간, 원하는 감각을 모두 골라주세요.”라는 검증 안내도 표시되어 폼 이벤트가 다시 연결된 것을 확인했다.

다만 초기 확인에서 화면 모드 버튼은 상태가 바뀌지 않았다. 이 제어 요소의 실제 선택자와 이벤트 연결을 추가로 점검해 함께 보완한다. Gemini 결과 호출은 정적 Manus 미리보기 서버가 아니라 Vercel의 `api/recommend.py` 서버리스 함수와 `GEMINI_API_KEY`가 설정된 배포에서 검증해야 한다.

테마 버튼은 `.theme-toggle` 선택자이며, 실제 스타일 대상은 `.dark`가 아니라 `body.dark-mode`였다. 정확한 상태 이름으로 다시 확인한 결과 클릭 뒤 `dark-mode` 클래스와 본문 배경색이 함께 바뀌었다. 초기 점검은 잘못된 클래스 이름을 확인한 데서 생긴 오판이었으며, 테마 버튼 자체는 정상 동작한다.

정적 Manus 미리보기에는 Vercel의 Python 함수가 없으므로, 모든 필수 입력을 채운 뒤 루틴 생성 버튼을 누르면 Gemini 결과 대신 API 연결 실패가 날 수 있다. 이를 모호한 연결 오류가 아닌 Vercel 배포·환경 변수 설정 안내로 표시하도록 보완한다.

## 공개 배포 재확인

수정 체크포인트를 공개 배포한 뒤 같은 도메인을 다시 확인했다. 이전과 달리 첫 화면의 제목·설명·버튼·대표 이미지가 정상적으로 표시되어 공백 화면 문제가 해소되었다. 원인은 프로덕션 빌드에서 0바이트가 된 `/app.js`를 참조한 것이었고, Vite가 번들링하는 `/src/app.js` 모듈 진입점으로 바꿔 해결했다.
