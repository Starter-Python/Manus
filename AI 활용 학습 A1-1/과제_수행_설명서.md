# A1-1 과제 수행 설명서

이 문서는 **Python 콘솔 프롬프트 관리자**를 어떤 문제로 보고, 어떤 자료구조와 함수로 나누어 구현했는지 설명합니다. 단순히 완성된 코드를 실행하는 데서 그치지 않고, 입력값이 프로그램 안에서 어떻게 데이터가 되고 메뉴 기능으로 연결되는지 이해하는 것이 목적입니다.

> 핵심 목표는 “프롬프트를 리스트와 딕셔너리로 관리하고, 사용자의 메뉴 입력에 따라 데이터를 추가·조회·검색·변경하는 콘솔 프로그램”을 만드는 것입니다.

## 1. 문제를 기능으로 나누기

과제의 기능 요구를 한 덩어리의 코드로 작성하면 `main()` 함수가 지나치게 길어지고 수정하기 어려워집니다. 따라서 화면 출력, 입력 검증, 데이터 추가, 목록 출력, 검색, 즐겨찾기처럼 **사용자 관점의 기능 단위**로 함수를 나누었습니다. `main()`은 메뉴를 반복해서 보여 주고, 선택한 번호에 맞는 함수를 호출하는 역할만 담당합니다.

| 영역 | 주요 함수 | 역할 |
| --- | --- | --- |
| 초기 데이터 | `create_initial_prompts()` | 기본 예시 프롬프트를 실행별로 복사합니다. |
| 입력 검증 | `get_non_empty_input()`, `get_menu_choice()`, `get_prompt_index()` | 빈 값, 잘못된 메뉴, 범위를 벗어난 번호를 처리합니다. |
| 등록과 조회 | `add_prompt()`, `show_prompt_list()`, `show_prompts_by_category()` | 프롬프트를 추가하고 조건에 맞게 화면에 출력합니다. |
| 검색과 상세 | `find_prompts()`, `search_prompts()`, `show_prompt_detail()` | 키워드 검색과 전체 내용 조회를 처리합니다. |
| 즐겨찾기 | `toggle_favorite()`, `show_favorites()` | 상태를 바꾸고 즐겨찾기 항목만 모아 보여 줍니다. |
| 실행 제어 | `show_menu()`, `main()` | 메뉴를 반복 출력하고 기능 함수를 연결합니다. |

## 2. 데이터를 리스트와 딕셔너리로 설계한 이유

프롬프트는 여러 개가 필요하므로 전체 저장소에는 **리스트**를 사용했습니다. 한 프롬프트에는 제목, 내용, 카테고리, 즐겨찾기처럼 성격이 다른 값들이 함께 있으므로 각 항목에는 **딕셔너리**를 사용했습니다. 즉 `list[dict]` 형태로 데이터를 저장한 것입니다.

```python
{
    "title": "블로그 초안 작성",
    "content": "주제를 바탕으로 블로그 초안을 작성하세요.",
    "category": "텍스트 생성",
    "favorite": True,
}
```

| 키 | 값의 의미 | 사용되는 기능 |
| --- | --- | --- |
| `title` | 프롬프트의 짧은 이름 | 목록 보기, 검색, 상세 보기 |
| `content` | 실제로 사용할 프롬프트 전문 | 검색, 상세 보기 |
| `category` | 프롬프트 분류 | 추가, 카테고리별 조회 |
| `favorite` | 즐겨찾기 상태인 불리언 값 | 목록의 별 표시, 즐겨찾기 전환·조회 |

기본 데이터는 `DEFAULT_PROMPTS`에 두고, 실행할 때 `deepcopy()`로 복사합니다. 이렇게 하면 한 번 실행 중에 즐겨찾기를 바꾸거나 항목을 추가하더라도 원본 예시 데이터가 바뀌지 않습니다. 따라서 프로그램을 다시 실행했을 때 요구사항대로 기본 상태가 다시 만들어집니다.

## 3. 메뉴 반복 구조 이해하기

`main()` 함수는 `while True` 반복문을 사용합니다. 프로그램을 시작하면 기본 데이터를 만들고, 메뉴를 보여 준 뒤 사용자의 선택을 받습니다. 선택값은 `if`와 `elif` 조건문을 거쳐 해당 기능 함수로 이동합니다. 각 기능 함수가 끝나면 반복문의 다음 회차가 시작되므로 메뉴가 다시 표시됩니다.

```python
while True:
    show_menu()
    choice = get_menu_choice()

    if choice == "1":
        add_prompt(prompts)
    elif choice == "2":
        show_prompt_list(prompts)
    elif choice == "8":
        break
```

`get_menu_choice()` 안에서도 반복문을 사용합니다. 사용자가 `1`부터 `8` 이외의 값을 입력하면 바로 프로그램을 종료하지 않고 안내 문구를 출력한 뒤 다시 입력받습니다. 이 방식은 메뉴 번호, 카테고리 번호, 프롬프트 번호 검증에도 같은 원리로 적용했습니다.

## 4. 프롬프트 추가 흐름

프롬프트 추가는 사용자 입력을 데이터 딕셔너리로 바꾸고 리스트 끝에 넣는 과정입니다. 제목과 내용은 `get_non_empty_input()`으로 받기 때문에 공백만 입력하면 다시 입력하도록 되어 있습니다. 카테고리는 기본 목록에서 번호로 선택하거나 `0`을 입력해 직접 작성할 수 있습니다.

| 단계 | 사용자 행동 | 프로그램 내부 처리 |
| --- | --- | --- |
| 1 | 메뉴에서 `1` 선택 | `add_prompt(prompts)`를 호출합니다. |
| 2 | 제목·내용 입력 | 빈 문자열이 아닌지 검사합니다. |
| 3 | 카테고리 선택 | 기본 카테고리 또는 직접 입력 문자열을 반환합니다. |
| 4 | 등록 완료 | `favorite: False`를 포함한 딕셔너리를 `append()`합니다. |
| 5 | 다음 메뉴 | 같은 `prompts` 리스트를 계속 사용합니다. |

새 카테고리를 직접 입력한 경우에는 `get_view_categories()`가 기존 데이터에서 사용자 정의 카테고리를 찾아 카테고리별 조회 목록 끝에 추가합니다. 따라서 직접 만든 카테고리도 조회 기능에서 빠지지 않습니다.

## 5. 목록, 검색, 상세 보기의 차이

세 기능은 모두 데이터를 화면에 보여 주지만 목적이 다릅니다. 목록은 모든 항목의 요약을 보여 주고, 검색은 제목 또는 내용에 키워드가 있는 항목만 골라 요약을 보여 줍니다. 상세 보기는 번호를 선택해 한 항목의 전체 내용을 보여 줍니다.

| 기능 | 선택 기준 | 출력 수준 | 핵심 로직 |
| --- | --- | --- | --- |
| 전체 목록 | 없음 | 모든 항목의 요약 | `show_prompt_list(prompts)` |
| 카테고리별 조회 | 카테고리 이름 | 조건에 맞는 항목의 요약 | 리스트 컴프리헨션으로 필터링 |
| 검색 | 제목 또는 내용의 키워드 | 일치 항목의 요약 | `find_prompts()`와 `casefold()` |
| 상세 보기 | 프롬프트 번호 | 한 항목의 전체 필드 | `get_prompt_index()` 후 딕셔너리 접근 |

검색에는 `casefold()`를 사용했습니다. 영어 대소문자가 섞인 검색어라도 비교를 안정적으로 처리하기 위한 방법입니다. 검색 결과가 없거나 특정 카테고리에 데이터가 없다면 빈 리스트가 전달되고, `show_prompt_list()`가 “저장된 프롬프트가 없습니다.”라는 안내를 출력합니다.

## 6. 즐겨찾기 상태를 바꾸는 방법

즐겨찾기는 별도의 목록을 새로 저장하지 않고 기존 딕셔너리의 `favorite` 값만 `True`와 `False`로 바꿉니다. `not` 연산자는 현재 상태를 반대로 바꾸므로 동일한 메뉴로 추가와 해제를 모두 처리할 수 있습니다.

```python
prompt["favorite"] = not prompt["favorite"]
```

이후 `show_favorites()`는 리스트 컴프리헨션으로 `favorite` 값이 참인 항목만 골라 `show_prompt_list()`에 전달합니다. 데이터는 하나만 유지하고, 필요한 화면에서 조건에 맞는 항목만 만들어 쓰는 방식입니다.

## 7. 테스트와 직접 실행으로 확인한 내용

자동화 테스트는 사용자 입력이 필요 없는 핵심 로직을 우선 확인합니다. 기본 데이터가 3개 이상인지, 필수 키가 모두 있는지, 실행마다 데이터가 독립적인지, 번호 검증이 올바른지, 직접 입력한 카테고리가 조회 목록에 포함되는지를 검사합니다. 검색 함수도 키워드 일치와 빈 결과를 테스트합니다.

| 검증 방법 | 명령 또는 입력 | 확인 대상 |
| --- | --- | --- |
| 단위 테스트 | `python3 -m unittest discover -s tests -v` | 데이터 구조와 순수 함수의 결과 |
| 문법 검사 | `python3 -m py_compile prompt_manager.py` | 파이썬 문법 오류 여부 |
| 통합 실행 | `python3 prompt_manager.py` | 메뉴 이동, 추가, 목록, 검색, 상세, 즐겨찾기, 종료 흐름 |
| Git 확인 | `git log --oneline --graph` | 기능 단위 커밋과 브랜치 병합 이력 |

## 8. Git 작업 방식

과제 파일은 `Manus` 저장소의 `AI 활용 학습 A1-1` 폴더 안에서 관리합니다. 기능을 한 번에 모두 커밋하지 않고, 설정·핵심 프로그램·목록 기능·검색·상세 보기·즐겨찾기·테스트·문서처럼 의미 있는 변경 단위로 나눠 커밋합니다. 목록 출력 형식 개선은 별도 기능 브랜치에서 작업한 뒤 `main`에 병합하여, 브랜치 생성과 병합 흐름도 기록합니다.

> Git은 코드를 “저장”하는 도구를 넘어, 어떤 기능을 언제 왜 바꾸었는지 되돌아볼 수 있게 하는 변경 이력 관리 도구입니다. 작은 기능 단위의 커밋 메시지는 과제를 설명하고 복습하는 데에도 도움이 됩니다.
